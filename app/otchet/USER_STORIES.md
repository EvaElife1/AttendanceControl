# USER STORIES — AttendanceControl

**Проект:** «Система контроля посещаемости студентов»  
**Пользователь:** преподаватель / куратор учебной группы

---

## Спринт 1 — Основа приложения

### US-01. Просмотр главного меню
**Как преподаватель, я хочу видеть главное меню приложения, чтобы быстро переходить к нужным разделам.**

**Критерии приёмки:**
- На экране отображается название приложения.
- Присутствуют три кнопки: «Студенты», «Отметить посещаемость», «Статистика».
- Нажатие на кнопку открывает соответствующий экран.
- Приложение не падает при переходах.
- Учитываются отступы под статус-бар и навигационную панель устройства.

**Статус:** Выполнено.

---

### US-02. Навигация между разделами
**Как преподаватель, я хочу переходить между разделами приложения, чтобы работать с разными функциями.**

**Критерии приёмки:**
- Переходы реализованы через `Intent`.
- На каждом экране есть кнопка «Назад».
- Возврат на главный экран работает корректно.

**Статус:** Выполнено.

---

### US-03. Техническая готовность проекта
**Как команда разработки, мы хотим иметь настроенный проект и репозиторий для совместной работы.**

**Критерии приёмки:**
- Проект создан в Android Studio на Kotlin.
- Настроен `.gitignore` и создан Git-репозиторий.
- Приложение собирается и запускается на эмуляторе / устройстве с API 24+.

**Статус:** Выполнено.

---

## Спринт 2 — Управление студентами

### US-04. Добавление студента
**Как преподаватель, я хочу добавлять студентов, чтобы вести учёт группы.**

**Критерии приёмки:**
- Форма содержит три обязательных поля: фамилия, имя, учебная группа.
- Поля из одних пробелов не принимаются.
- После успешного добавления студент сразу отображается в списке.
- Поля формы очищаются после добавления.
- Показывается Toast «Студент добавлен».

**Статус:** Выполнено.

---

### US-05. Просмотр списка студентов
**Как преподаватель, я хочу видеть список всех студентов, сгруппированных по группе.**

**Критерии приёмки:**
- Список отображает фамилию, имя и группу каждого студента.
- Студенты сгруппированы: над первым студентом каждой группы показывается заголовок «Группа: …».
- Список обновляется после добавления и удаления.
- При пустом списке экран не падает.
- Нижняя часть списка не перекрывается навигационной панелью устройства.

**Статус:** Выполнено.

---

### US-06. Удаление студента
**Как преподаватель, я хочу удалять студента, чтобы убирать ошибочные или неактуальные записи.**

**Критерии приёмки:**
- Удаление выполняется с диалогом подтверждения (кнопки «Удалить» / «Отмена»).
- После удаления список обновляется, счётчик студентов уменьшается.
- Приложение не падает.

**Статус:** Выполнено.

---

### US-07. Валидация ввода данных
**Как преподаватель, я хочу, чтобы приложение не принимало некорректные данные.**

**Критерии приёмки:**
- Пустые поля отклоняются с указанием конкретного поля: «Введите фамилию» / «Введите имя» / «Введите группу».
- Поля из одних пробелов обрабатываются как пустые.
- Ошибки проверяются в порядке: фамилия → имя → группа.

**Статус:** Выполнено (`StudentValidator`).

---

## Спринт 3 — Отметка посещаемости

### US-08. Задание предмета и даты занятия
**Как преподаватель, я хочу указать предмет и дату, чтобы привязать отметки к конкретному занятию.**

**Критерии приёмки:**
- Есть поле «Дисциплина / Тема» и поле «Дата».
- Оба поля обязательны — без них нельзя сохранить отметки.
- Дата проверяется на формат ГГГГ-ММ-ДД и на корректность числа (нет 31 февраля и т.п.).
- При ошибке формата поле дата подсвечивается ошибкой.

**Статус:** Выполнено.

---

### US-09. Просмотр и отметка студентов
**Как преподаватель, я хочу видеть список всех студентов и выбирать статус для каждого.**

**Критерии приёмки:**
- После заполнения полей виден список всех студентов из базы данных.
- Для каждого студента доступны три статуса: «Присутствовал», «Отсутствовал», «Опоздал».
- Выбранный статус сохраняется при прокрутке списка.
- Нельзя поставить два статуса одному студенту одновременно.
- Нижняя часть списка не перекрывается навигационной панелью.

**Статус:** Выполнено.

---

### US-10. Сохранение отметок
**Как преподаватель, я хочу одним нажатием сохранить все отметки, чтобы не делать это по одной.**

**Критерии приёмки:**
- Кнопка «Сохранить отметки» недоступна для нажатия, пока не заполнены предмет и дата.
- Если у хотя бы одного студента не выбран статус — показывается предупреждение.
- После успешного сохранения показывается Toast «Посещаемость сохранена».

**Статус:** Выполнено.

---

## Спринт 4 — Постоянное хранение данных

### US-11. Сохранение студентов при перезапуске
**Как преподаватель, я хочу, чтобы добавленные студенты не пропадали после закрытия приложения.**

**Критерии приёмки:**
- После добавления студента и перезапуска приложения список студентов не пуст.
- Удалённые студенты не появляются после перезапуска.
- Данные хранятся в локальной базе Room (SQLite).

**Статус:** Выполнено.

---

### US-12. Сохранение отметок посещаемости
**Как преподаватель, я хочу, чтобы выставленные статусы сохранялись в базе для последующего анализа.**

**Критерии приёмки:**
- После сохранения отметок и перезапуска приложения данные посещаемости остаются в базе.
- Каждая запись привязана к студенту (studentId), дате и предмету.

**Статус:** Выполнено.

---

### US-13. Корректный первый запуск
**Как преподаватель, я хочу, чтобы приложение работало корректно с первого запуска, даже если база пуста.**

**Критерии приёмки:**
- При первом запуске список студентов пуст — приложение не падает.
- Экран статистики показывает заглушку «Нет данных» — приложение не падает.
- База данных создаётся автоматически при первом обращении.

**Статус:** Выполнено.

---

## Спринт 5 — Статистика и фильтрация

### US-14. Просмотр сводки посещаемости
**Как преподаватель, я хочу видеть общую картину посещаемости, чтобы быстро оценить ситуацию.**

**Критерии приёмки:**
- Три карточки с числами: «Присутствовал», «Отсутствовал», «Опоздал».
- Прогресс-бар и процент посещаемости: (Присутствовал + Опоздал) / Всего × 100%.
- Данные в карточках обновляются при изменении фильтров.
- При пустой базе показывается экран-заглушка «Нет данных».

**Статус:** Выполнено.

---

### US-15. Просмотр списка записей посещаемости с ФИО и группой
**Как преподаватель, я хочу видеть детальный список записей, чтобы знать кто, когда и на каком занятии присутствовал.**

**Критерии приёмки:**
- Каждая строка содержит: Фамилия Имя, группу, предмет, дату и цветной статус-чип.
- Список отсортирован по дате убывания (свежие записи сверху).
- Статус-чип раскрашен: зелёный — Присутствовал, красный — Отсутствовал, оранжевый — Опоздал.

**Статус:** Выполнено.

---

### US-16. Фильтрация записей по группе и статусу
**Как преподаватель, я хочу фильтровать список записей, чтобы видеть данные только по нужной группе или статусу.**

**Критерии приёмки:**
- Два компактных выпадающих списка в одной строке: «Группа» и «Статус».
- Список групп формируется динамически из реальных данных в базе.
- Список статусов фиксирован: «Все статусы» / «Присутствовал» / «Отсутствовал» / «Опоздал».
- При выборе фильтра список записей и карточки-счётчики обновляются мгновенно.
- Счётчик «X из Y» показывает количество отфильтрованных записей.
- При выборе «Все группы» / «Все статусы» показываются все данные.

**Статус:** Выполнено.

---

### US-17. Учёт системной навигационной панели
**Как пользователь, я хочу, чтобы содержимое экранов не перекрывалось навигационной панелью устройства.**

**Критерии приёмки:**
- На всех экранах последний элемент списка или кнопка видны полностью.
- Поддерживается как 3-кнопочная навигация, так и жестовая (gesture navigation).
- Статус-бар корректно учитывается в шапке каждого экрана.

**Статус:** Выполнено (`applyStatusBarPadding`, `applyNavigationBarPadding`, `applySystemBarsPadding`).

## Сущности базы данных

### StudentEntity (таблица `students`)
| Поле | Тип | Описание |
|---|---|---|
| `id` | Int (PK, auto) | Уникальный идентификатор |
| `firstName` | String | Имя |
| `lastName` | String | Фамилия |
| `groupName` | String | Группа |

### AttendanceEntity (таблица `attendance`)
| Поле | Тип | Описание |
|---|---|---|
| `id` | Int (PK, auto) | Уникальный идентификатор |
| `studentId` | Int (FK) | Ссылка на студента |
| `lessonDate` | String | Дата (ГГГГ-ММ-ДД) |
| `subject` | String | Дисциплина |
| `status` | String | «Присутствовал» / «Отсутствовал» / «Опоздал» |

## Известные ограничения (не баги)

| # | Описание |
|---|---|
| L-01 | Повторная отметка того же студента на то же занятие создаёт новую запись (нет уникального ограничения в БД) |
| L-02 | Фильтрация в статистике — только по группе и статусу (нет фильтра по студенту или дате) |
| L-03 | В списке статистики отображается не более 100 последних записей |
| L-04 | Нет синхронизации с облаком и нет авторизации |
