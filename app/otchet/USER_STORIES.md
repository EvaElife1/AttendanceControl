## Спринт 2. Студенты и учебные группы

### US-04. Добавление студента
**Как преподаватель, я хочу добавлять студентов в список, чтобы вести учёт учебной группы.**

**Критерии приёмки:**
- Форма содержит поля: фамилия, имя, учебная группа.
- Все поля обязательны.
- При пустых полях или полях из пробелов выводится сообщение об ошибке.
- После успешного добавления студент отображается в списке.
- Сообщение об успехе: «Студент добавлен».

**Статус:** Выполнено.

---

### US-05. Просмотр списка студентов
**Как преподаватель, я хочу видеть список всех студентов, чтобы быстро находить нужного.**

**Критерии приёмки:**
- Список отображается на отдельном экране.
- В списке видны фамилия, имя и группа.
- Список обновляется после добавления и удаления.
- При пустом списке отображается корректное состояние экрана.

**Статус:** Выполнено.

---

### US-06. Удаление студента
**Как преподаватель, я хочу удалять студента из списка, чтобы убирать ошибочные или неактуальные записи.**

**Критерии приёмки:**
- Удаление выполняется с подтверждением.
- После удаления список обновляется.
- Приложение не завершается аварийно.

**Статус:** Выполнено.

---

### US-07. Валидация ввода данных
**Как преподаватель, я хочу, чтобы приложение не принимало пустые или некорректные данные, чтобы список оставался чистым.**

**Критерии приёмки:**
- Пустые поля отклоняются.
- Поля из одних пробелов отклоняются.
- При ошибке выводится сообщение: «Заполните все обязательные поля».

**Статус:** Выполнено.

---

### US-08. Понятные сообщения об ошибках
**Как преподаватель, я хочу видеть понятные сообщения при вводе данных, чтобы понимать, что нужно исправить.**

**Критерии приёмки:**
- Сообщение при пустых полях: «Заполните все обязательные поля».
- Сообщение при успешном добавлении: «Студент добавлен».

**Статус:** Выполнено.

---

### US-09. Сохранение данных в рамках сеанса
**Как преподаватель, я хочу, чтобы добавленные студенты сохранялись до перезапуска приложения, чтобы не вводить их повторно в течение занятия.**

**Критерии приёмки:**
- Данные сохраняются в памяти в рамках текущего сеанса.
- После перезапуска данные могут быть утеряны (постоянное хранение будет в Спринте 4).

**Статус:** Выполнено.

# USER STORIES — Спринт 3
**Проект:** Система контроля посещаемости студентов  
**Роль:** Product Owner  
**Тема спринта:** Занятия и отметка посещаемости

---

## 1. Описание сценария занятия

**Основной сценарий работы преподавателя:**

1. Преподаватель открывает экран «Отметить посещаемость».
2. Выбирает **учебную группу**.
3. Выбирает **дату занятия**.
4. (При необходимости) указывает **дисциплину / тему** занятия.
5. Приложение показывает список студентов выбранной группы.
6. Преподаватель назначает каждому студенту один из статусов:
    - **Присутствовал**
    - **Отсутствовал**
    - **Опоздал**
7. После выставления статусов преподаватель сохраняет результаты.
8. Отметки сохраняются и потом используются в статистике.

---

## 2. Согласованные статусы посещаемости

| Статус            | Что означает                          | Как отображается |
|-------------------|---------------------------------------|------------------|
| **Присутствовал** | Студент был на занятии вовремя        | Зелёный / ✓     |
| **Отсутствовал**  | Студент не явился на занятие          | Красный / ✗     |
| **Опоздал**       | Студент пришёл, но с опозданием       | Жёлтый / ⚠      |

**Правило:**  
На одно занятие у одного студента может быть **только одна итоговая отметка**.  
Если преподаватель меняет статус — предыдущий статус заменяется новым.

---

## 3. User Stories

### US-08. Создание занятия
**Как** преподаватель,  
**я хочу** выбрать группу и дату занятия,  
**чтобы** начать отмечать посещаемость именно по этому занятию.

**Критерии приёмки:**
- [ ] Есть возможность выбрать группу
- [ ] Есть возможность выбрать дату
- [ ] Можно указать дисциплину/тему (необязательно)
- [ ] После выбора открывается список студентов этой группы

---

### US-09. Отметка статуса студента
**Как** преподаватель,  
**я хочу** назначить каждому студенту статус (Присутствовал / Отсутствовал / Опоздал),  
**чтобы** зафиксировать посещаемость.

**Критерии приёмки:**
- [ ] Для каждого студента можно выбрать один из трёх статусов
- [ ] Статус можно изменить до сохранения
- [ ] Нельзя поставить два статуса одному студенту на одном занятии
- [ ] После сохранения отметка сохраняется

---

### US-10. Обработка пустого списка
**Как** преподаватель,  
**я хочу** видеть понятное сообщение, если в группе нет студентов,  
**чтобы** понимать, почему список пустой.

**Критерии приёмки:**
- [ ] Если студентов в группе нет — показывается сообщение «В этой группе пока нет студентов»
- [ ] Приложение не падает

---

### US-11. Одна отметка на студента и занятие
**Как** преподаватель,  
**я хочу**, чтобы на одно занятие у студента была только одна итоговая отметка,  
**чтобы** статистика считалась правильно.

**Критерии приёмки:**
- [ ] При повторной отметке того же студента на том же занятии старая отметка заменяется новой
- [ ] В базе / списке не появляется дублей

---

## 4. Правила для команды разработки

- Статусы только три: **Присутствовал**, **Отсутствовал**, **Опоздал**
- Одна отметка = один студент + одно занятие
- Можно менять статус до окончательного сохранения
- Пустой список студентов должен обрабатываться корректно
- Все статусы должны быть одинаково отражены в коде, тестах и интерфейсе
