## Спринт 2. Студенты и учебные группы

### US-04. Добавление студента
**Как преподаватель, я хочу добавлять студентов в список, чтобы вести учёт учебной группы.**

**Критерии приёмки:**
- Форма содержит поля: фамилия, имя, учебная группа.
- Все поля обязательны.
- При пустых полях или полях из пробелов выводится сообщение об ошибке.
- После успешного добавления студент отображается в списке.
- Сообщение об успехе: «Студент добавлен».

**Статус:** Выполнено.

---

### US-05. Просмотр списка студентов
**Как преподаватель, я хочу видеть список всех студентов, чтобы быстро находить нужного.**

**Критерии приёмки:**
- Список отображается на отдельном экране.
- В списке видны фамилия, имя и группа.
- Список обновляется после добавления и удаления.
- При пустом списке отображается корректное состояние экрана.

**Статус:** Выполнено.

---

### US-06. Удаление студента
**Как преподаватель, я хочу удалять студента из списка, чтобы убирать ошибочные или неактуальные записи.**

**Критерии приёмки:**
- Удаление выполняется с подтверждением.
- После удаления список обновляется.
- Приложение не завершается аварийно.

**Статус:** Выполнено.

---

### US-07. Валидация ввода данных
**Как преподаватель, я хочу, чтобы приложение не принимало пустые или некорректные данные, чтобы список оставался чистым.**

**Критерии приёмки:**
- Пустые поля отклоняются.
- Поля из одних пробелов отклоняются.
- При ошибке выводится сообщение: «Заполните все обязательные поля».

**Статус:** Выполнено.

---

### US-08. Понятные сообщения об ошибках
**Как преподаватель, я хочу видеть понятные сообщения при вводе данных, чтобы понимать, что нужно исправить.**

**Критерии приёмки:**
- Сообщение при пустых полях: «Заполните все обязательные поля».
- Сообщение при успешном добавлении: «Студент добавлен».

**Статус:** Выполнено.

## Спринт 3. Занятия и отметка посещаемости

### US-09. Создание занятия
**Как преподаватель, я хочу выбрать группу и дату занятия, чтобы начать отмечать посещаемость именно по этому занятию.**

**Критерии приёмки:**
- Есть возможность выбрать группу.
- Есть возможность выбрать дату.
- Можно указать дисциплину/тему (необязательно).
- После выбора открывается список студентов этой группы.

**Статус:** Выполнено.

---

### US-10. Отметка статуса студента
**Как преподаватель, я хочу назначить каждому студенту статус (Присутствовал / Отсутствовал / Опоздал), чтобы зафиксировать посещаемость.**

**Критерии приёмки:**
- Для каждого студента можно выбрать один из трёх статусов.
- Статус можно изменить до сохранения.
- Нельзя поставить два статуса одному студенту на одном занятии.
- После сохранения отметка сохраняется.

**Статус:** Выполнено.

---

### US-11. Одна отметка на студента и занятие
**Как преподаватель, я хочу, чтобы на одно занятие у студента была только одна итоговая отметка, чтобы статистика считалась правильно.**

**Критерии приёмки:**
- При повторной отметке того же студента на том же занятии старая отметка заменяется новой.
- В базе или списке не появляется дублей.

**Статус:** Выполнено.

## Спринт 4. Постоянное хранение данных

### Согласование сущностей данных

Для перехода на Room согласованы следующие сущности:
- **StudentEntity:** `id` (первичный ключ), `firstName`, `lastName`, `groupName`.
- **AttendanceEntity:** `id` (первичный ключ), `studentId` (внешний ключ), `lessonDate`, `subject`, `status`.
- **Lesson (при необходимости):** `id`, `groupName`, `lessonDate`, `subject`. Если `Lesson` оформляется отдельно, `Attendance` должна ссылаться на занятие по идентификатору.

---

### US-12. Сохранение студентов при перезапуске
**Как преподаватель, я хочу, чтобы добавленные студенты сохранялись после закрытия и повторного открытия приложения, чтобы не вводить их заново.**

**Критерии приёмки:**
- После добавления студента и перезапуска приложения список студентов не пуст.
- Удалённые студенты не появляются после перезапуска.
- Данные хранятся в локальной базе Room (SQLite).

**Статус:** Выполнено.

---

### US-13. Сохранение отметок посещаемости
**Как преподаватель, я хочу, чтобы выставленные статусы посещаемости сохранялись в базе данных, чтобы можно было вернуться к ним позже и построить статистику.**

**Критерии приёмки:**
- После сохранения отметок и перезапуска приложения данные посещаемости остаются в базе.
- Записи привязаны к конкретному студенту и занятию (дата, дисциплина).

**Статус:** Выполнено.

---

### US-14. Поведение при первом запуске (пустая база)
**Как преподаватель, я хочу, чтобы при первом запуске приложение работало корректно, даже если база данных пуста.**

**Критерии приёмки:**
- При первом запуске список студентов пуст, приложение не падает.
- Экран статистики корректно обрабатывает отсутствие отметок.
- База данных создаётся автоматически при первом обращении.

**Статус:** Выполнено.

## Требования к карточке студента и отметкам

**Сущность Student:**
- `id` — уникальный идентификатор (автогенерация).
- `firstName` — имя.
- `lastName` — фамилия.
- `groupName` — учебная группа.

**Сущность Attendance:**
- `id` — уникальный идентификатор.
- `studentId` — ссылка на студента.
- `lessonDate` — дата занятия.
- `subject` — дисциплина/тема.
- `status` — статус (Присутствовал / Отсутствовал / Опоздал).
