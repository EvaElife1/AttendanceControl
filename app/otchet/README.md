# AttendanceControl

**Проект:** «Система контроля посещаемости студентов»  
**Роль:** Product Owner (PO)  

---

## 1. Назначение

Android-приложение для учёта посещаемости студентов колледжа.  
Основной пользователь — преподаватель или куратор учебной группы.  
Приложение предназначено для локального использования на одном Android-устройстве.

---

## 2. Требования

- Android Studio
- Kotlin
- Android SDK
- Git (для контроля версий)
- Room (SQLite) для локального хранения данных

---

## 3. Запуск проекта

1. Открыть проект в Android Studio.
2. Выполнить синхронизацию Gradle.
3. Собрать проект (`Build → Make Project`).
4. Запустить на эмуляторе или физическом устройстве.

---

## 4. Текущие возможности

### Спринт 1
- Главный экран с названием приложения.
- Кнопки: «Студенты», «Отметить посещаемость», «Статистика».
- Навигация между экранами через `Intent`.
- Экраны-заготовки: `StudentsActivity`, `AttendanceActivity`, `StatisticsActivity`.

### Спринт 2
- Экран списка студентов.
- Форма добавления студента: фамилия, имя, учебная группа.
- Валидация обязательных полей.
- Удаление студента с подтверждением.
- Сообщения: «Студент добавлен», «Заполните все обязательные поля».

### Спринт 3
- Экран занятия и отметки посещаемости.
- Выбор статуса для каждого студента через `RadioGroup` (Присутствовал / Отсутствовал / Опоздал).
- Валидация введённой даты (формат ГГГГ-ММ-ДД).
- Сохранение отметок в рамках текущего сеанса.

### Спринт 4
- Подключена локальная база данных Room (SQLite).
- Созданы сущности (`Entity`), интерфейсы доступа к данным (`DAO`) и класс базы данных (`AppDatabase`).
- Все операции со студентами и посещаемостью переведены на работу с базой данных.
- Данные сохраняются между запусками приложения (студенты и отметки не пропадают после перезапуска).
- Корректно обрабатывается первый запуск с пустой базой данных.

---

## 5. Структура приложения и базы Room

- `StudentEntity` — таблица `students` (поля: `id`, `firstName`, `lastName`, `groupName`).
- `AttendanceEntity` — таблица `attendance` (поля: `id`, `studentId`, `lessonDate`, `subject`, `status`).
- `StudentDao`, `AttendanceDao` — интерфейсы для выполнения запросов к базе (чтение, добавление, удаление).
- `AppDatabase` — класс базы данных, связывающий сущности и DAO.
- `StudentsActivity` и `AttendanceActivity` — UI-экраны, которые читают и сохраняют данные через DAO.

---

## 6. Ограничения

- Приложение использует локальное хранилище (Room/SQLite). Синхронизация с облаком отсутствует.
- Нет авторизации и разделения по пользователям (предполагается один преподаватель на устройстве).
- Статистика и фильтрация находятся в разработке (Спринт 5).
