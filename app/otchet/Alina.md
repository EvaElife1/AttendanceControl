## 2. Реализованный функционал

- Модель `Student`: поля id, firstName, lastName, groupName.
- Экран «Студенты»: поля ввода «Фамилия», «Имя», «Группа», кнопка «Добавить» и список студентов.
- Проверка ввода: пустые поля и поля из одних пробелов отклоняются, у поля показывается сообщение об ошибке.
- Добавление: корректная запись появляется в списке, поля очищаются, показывается сообщение «Студент добавлен».
- Удаление: кнопка «Удалить» в строке списка открывает диалог подтверждения; после подтверждения студент исчезает из списка, при отмене остаётся.
- Список обновляется после добавления и удаления.

## 4. Технические решения

- Язык: Kotlin, интерфейс: XML + Activity (View-based).
- Список выводится через `RecyclerView` с отдельным адаптером `StudentAdapter`.
- Данные пока хранятся во временной коллекции в памяти (`MutableList<Student>`); постоянное хранение через Room планируется в спринте 4.
- Идентификатор студента формируется счётчиком `nextId`.
- Ошибки ввода показываются через `setError` у полей, подтверждение удаления через `AlertDialog`.
- Корневому элементу экрана сохранён `android:id="@+id/studentsRoot"`, на него опираются UI-тесты QA.
- Изменения выполнены в отдельной ветке `feature/add-student`, оформлен Pull Request в `master`.

## 2. Данные, подлежащие сохранению

Для обеспечения работы приложения между запусками (после закрытия и повторного открытия) необходимо сохранять следующие данные:
1. **Студенты:** ФИО и учебная группа.
2. **Занятия:** Дата, дисциплина/тема, группа.
3. **Посещаемость:** Кто из студентов, на каком занятии и с каким статусом (Присутствовал / Отсутствовал / Опоздал).

---

## 3. Согласованные сущности данных (для Room)

Для взаимодействия с базой данных SQLite через Room согласованы следующие сущности (Entity):

**1. Student (Студент):**
- `id` (Primary Key, autoGenerate) — уникальный идентификатор.
- `firstName` — имя.
- `lastName` — фамилия.
- `groupName` — учебная группа.

**2. Attendance (Отметка посещаемости):**
- `id` (Primary Key, autoGenerate) — уникальный идентификатор записи.
- `studentId` (Foreign Key) — идентификатор студента, к которому относится отметка.
- `lessonDate` — дата занятия.
- `subject` — дисциплина / тема.
- `status` — статус (Присутствовал / Отсутствовал / Опоздал).

**3. Lesson (Занятие) — опционально:**
- `id` (Primary Key) — идентификатор занятия.
- `groupName` — группа.
- `lessonDate` — дата.
- `subject` — дисциплина.
  *(Если `Lesson` оформляется отдельной сущностью, `Attendance` должна ссылаться на занятие по его ID. Модель должна одинаково отражаться в коде, тестах и документации).*

---

## 4. Поведение при первом запуске и пустой базе

- **Инициализация:** При первом запуске приложения база данных Room создаётся автоматически. Никаких ошибок или вылетов происходить не должно.
- **Пустые списки:** Если база пуста, экран студентов и экран посещаемости должны отображать пустые списки с понятным сообщением (например, «Список студентов пуст»), а не пустой белый экран.
- **Защита от Null:** Все запросы к базе данных (чтение списка) должны корректно обрабатывать ситуацию, когда данных еще нет (возвращать пустой список, а не `null`).
