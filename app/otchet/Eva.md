| Статус            | Значение                                      |
|-------------------|-----------------------------------------------|
| Присутствовал     | Студент был на занятии вовремя                |
| Отсутствовал      | Студент не явился на занятие                  |
| Опоздал           | Студент пришёл, но с опозданием               |

### 2.3. Правило одной отметки
Определено и зафиксировано важное бизнес-правило:  
**На одно занятие у одного студента может быть только одна итоговая отметка.**  
При изменении статуса старая отметка заменяется новой.

### 2.4. User Stories
Подготовлены User Stories:

- **US-08** — Создание занятия (выбор группы и даты)
- **US-09** — Отметка статуса студента
- **US-10** — Обработка пустого списка студентов
- **US-11** — Правило одной отметки на студента и занятие

Для каждой истории прописаны критерии приёмки.

---

## 2. Реализованный функционал

В рамках спринта была внедрена библиотека **Room** для постоянного хранения данных.

**Что изменилось:**
- Ранее данные хранились в обычных списках `mutableListOf()` и терялись при перезапуске приложения.
- Теперь данные сохраняются в локальную базу данных SQLite на устройстве.
- Все операции с базой данных выполняются асинхронно (в фоновом потоке) с помощью корутин (`Coroutines`), чтобы не блокировать интерфейс.
