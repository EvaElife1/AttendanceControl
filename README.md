# AttendanceControl

**Проект:** «Система контроля посещаемости студентов»

---

## 1. Назначение

Android-приложение для учёта посещаемости студентов.  
Основной пользователь — преподаватель или куратор учебной группы.  
Приложение работает локально на одном Android-устройстве, не требует интернета и авторизации.

---

## 2. Технологии

| Компонент | Версия / Описание |

## 5. Структура базы данных (Room)

### Таблица `students`
| Поле | Тип | Описание |
|---|---|---|
| `id` | Int (PK, автогенерация) | Уникальный идентификатор |
| `firstName` | String | Имя студента |
| `lastName` | String | Фамилия студента |
| `groupName` | String | Название / номер группы |

### Таблица `attendance`
| Поле | Тип | Описание |
|---|---|---|
| `id` | Int (PK, автогенерация) | Уникальный идентификатор |
| `studentId` | Int (FK → students.id) | Ссылка на студента |
| `lessonDate` | String | Дата занятия (ГГГГ-ММ-ДД) |
| `subject` | String | Дисциплина / тема |
| `status` | String | «Присутствовал» / «Отсутствовал» / «Опоздал» |

### DAO и вспомогательные классы
- `StudentDao` — CRUD-операции со студентами
- `AttendanceDao` — вставка, чтение, агрегация по статусам, JOIN с таблицей студентов
- `AppDatabase` — Singleton, собирает сущности и DAO
- `StatusCount` — data class для агрегирующего запроса (статус + количество)
- `AttendanceWithStudent` — data class для JOIN-запроса (посещаемость + ФИО + группа)

## 6. Реализованные возможности

### Спринт 1 — Основа приложения
- Главный экран с тремя кнопками-разделами
- Навигация между экранами через `Intent`
- Экраны-заготовки (`StudentsActivity`, `AttendanceActivity`, `StatisticsActivity`)

### Спринт 2 — Управление студентами
- Форма добавления студента (фамилия, имя, группа)
- Валидация: пустые поля и поля из пробелов не принимаются
- Список студентов с группировкой по номеру группы
- Удаление студента с диалогом подтверждения

### Спринт 3 — Отметка посещаемости
- Ввод предмета и даты занятия
- Валидация даты (формат ГГГГ-ММ-ДД, проверка корректности числа)
- Выбор статуса для каждого студента через `RadioGroup`
- Восстановление выбранного статуса при прокрутке списка

### Спринт 4 — Постоянное хранение данных
- Подключена Room (SQLite): данные сохраняются между запусками
- Все операции (добавление студентов, сохранение отметок) работают через DAO
- Корректное поведение при пустой базе (первый запуск)

### Спринт 5 — Статистика и фильтрация
- Сводные карточки: Присутствовал / Отсутствовал / Опоздал
- Прогресс-бар уровня посещаемости (%)
- Список последних записей с ФИО, группой, предметом, датой и статус-чипом
- Фильтрация по группе и статусу (компактные спиннеры в одну строку)
- Счётчик «X из Y» отображает количество записей после фильтрации
- Сводные карточки пересчитываются при изменении фильтра
- Экран «Нет данных» при пустой базе
- Учёт системной навигационной панели (insets) на всех экранах

## 9. Ограничения

- Только локальное хранилище (Room/SQLite). Синхронизация с облаком не реализована.
- Нет авторизации. Предполагается один преподаватель на устройстве.
- Нет ограничения уникальности: повторная отметка одного студента на то же занятие создаёт новую запись (не перезаписывает старую).
- Фильтрация в статистике работает на стороне клиента (до 100 последних записей).
